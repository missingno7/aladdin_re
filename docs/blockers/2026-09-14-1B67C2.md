# Blocker: 1B67C2 (spawn dispatcher child)

## Where

Entry PC `1B67C2`, spawn dispatcher child (`--parent 1AE46C` census, kind
`00`). Caller is the spawn dispatcher's JSR at `1AE46C` (the same existing
gate as every other recovered spawn child this stint), reached with the
object record in A5 and the callback in A4, exactly like the 17 spawn
children already recovered.

## Code

`DATA_STRUCTURE` (a new pointer/state domain -- the global PRNG seed at
`FF7DEA` -- no existing `game.*` semantic function names it), compounded
with a branch tree substantially larger than any recipe covers.

## Observed

`frontier_ledger.py` on `artifacts/spawn-closures4` ranks this entry at
211 fallbacks, second only to the (now-mostly-declined) 1B6C0E family.
The census (`artifacts/evidence/spawn/index.json`) retained **23 distinct
path classes** for this one entry (`1B67C2-kind00-p0..p22`), every one of
them calling at least `1B3032` (twice in most rows) plus `1B5256` and
`1B6794`; the largest retained fixture (`p13`) traces to 414 instructions.
None of the 23 rows exercises a signature with only one call, so the
`D7 >= 0xC8` skip-first-spawn arm (see below) is never the primary
recorded path -- every retained fixture takes at least one spawn.

Facts traced by hand-walking `factcheck.py facts <fixture> --path` (not
counted, only read) on `1B67C2-kind00-p1.state` (the shortest retained
row, 131 instructions) and `1B67C2-kind00-p7.state` (145 instructions,
the only retained row that reaches the *second* RNG-gated cap check)
establish this structure:

1. `1B67C2`: `BSR 1B3032` (the PRNG, see below), then `CMPI.B #$C8,D7` /
   `BCC` -- an unobserved skip-first-spawn arm when the roll is >= 200.
2. Not skipped: `LEA 1B7DA0,A6` / `BSR 1B5256` (`SPAWN_REGION_REVERSE_ENTRY`,
   already-proven allocator, template `0x1B7DA0`) -- an ordinary spawn,
   already handled by every other reverse-pool caller this stint.
3. `BNE $1B6800` on the allocator's own Z flag (allocation failure skips
   directly to the shared exit, the familiar `+26/+2` shape) -- only
   observed as "not taken" in every retained fixture.
4. On success: `ADDI.W #$8,$4(A5)` (Y += 8) and `EORI.B #$FF,$9(A5)`
   (flip all bits of record+9), then `BSR 1B6794` -- a second, nested
   subroutine that itself:
   a. `BSR 1B3032` (PRNG roll #2), `ANDI.W #$7,D7` / `SUBI.W #$3,D7` /
      `ADD.W D7,$2(A5)` (X += (roll & 7) - 3, a signed jitter),
   b. `BSR 1B3032` (PRNG roll #3), `BTST.B #0,D7` / `BEQ` -- bit 0 of the
      roll conditionally writes a fixed script pointer (`MOVE.L
      #$1241FC,$20(A5)`),
   c. `BTST.B #1,D7` / `BEQ` -- bit 1 of the *same* roll branches; every
      retained fixture takes the branch straight to `RTS` at `1B67C0`.
      The bit-1-clear continuation is **not characterized** -- it was not
      reached in any attempt and may fall through to more code between
      `1B67BA` and `1B67C0` that was not traced.
5. `1B67C2-kind00-p7.state` (the 4-call row) shows a **second**,
   independently-gated cap check reached after the first spawn's own
   processing: `CMPI.B #$C8,D7` / `BCC 1B6800` at `1B67E0`, taken in that
   fixture -- i.e. a *second* spawn attempt, structurally mirroring the
   first (its own `BSR 1B5256`-or-similar body was not reached in the
   traced fixture because the cap check declined it). Rows with two full
   `1B5256`/`1B6794` call pairs (e.g. `p0`, `p2`, `p4`, `p6`, `p8`-`p10`,
   `p13`-`p15`, `p18`-`p22`) show this second spawn actually firing, with
   its own allocator, template and `1B6794`-shaped tail -- not yet
   distinguished from the first spawn's own constants (may reuse the same
   template, or use a distinct one; not traced instruction-by-instruction
   for this stint).

The PRNG itself (`1B3032`, called 2-3 times per occurrence) is a bounded,
17-instruction, RAM-only, no-native-call subroutine over the global 4-byte
seed at `FF7DEA`:

```
d1 = seed
d2 = d1 + 7
d1 = d1 << 1          (d1 *= 2)
d1 = d1 << 1          (d1 *= 4)
d3 = d1                (d3 = seed * 4)
d1 = d1 << 1          (d1 *= 8)
d1 = d1 + d2           (+= seed + 7)
d1 = d1 + d3           (+= seed * 4)
                        -- new_seed = 13*seed + 7 (mod 2^32)
seed = d1               (write back to FF7DEA)
d2 = d1; d2 = swap.w(d2)
d1 = d1 XOR.w d2        (word XOR only, low 16 bits)
d7 = low16(d1)          (the "random" output byte/word consumers read)
```

This is a plain LCG (`new_seed = 13*seed + 7`); the output is
`low16(new_seed) XOR swap16(new_seed)`. It is fully deterministic given
the seed and would need one new `game.*` function (e.g.
`advance_rng(seed) -> (new_seed, output)`) plus a boundary-level cost
model for the fixed 17-instruction body -- straightforward on its own.

## Why the recipe does not fit

None of section 4's two recipes (RAM-only leaf returning to its caller;
branch with one sound call) individually cover this entry's *shape*: it
is RAM-only (no native calls, matching the first recipe's domain), but it
is not a single guard-and-return or a single allocator call -- it is two
independently RNG-gated allocator calls, each followed by its own
RNG-gated position jitter and two-bit conditional script write, with at
least one branch (`1B67BA` bit-1-clear) never observed and therefore
uncharacterized. Recovering it correctly would mean either treating it as
one very large multi-branch leaf (in the spirit of the already-recovered
36-path-class Type-6E contact leaf) or splitting it into the two
spawn attempts as separate "arms" the way 1B6C0E's VDP arm was declined --
but unlike 1B6C0E, neither spawn attempt here is closed off by a hard
device-port wall; both are just RNG-gated RAM writes that a stronger pass
could fully own once the uncharacterized bit-1-clear continuation and the
second spawn's own constants (template, script pointer) are traced.

## What was tried

- Read `facts --path` on the two shortest retained rows (`p1`, `p7`) and
  the longest (`p13`'s summary only, not full path) to establish the
  overall shape above.
- Decoded the `1B3032` PRNG body instruction-by-instruction from the
  traced facts (not from ROM disassembly alone) and derived the closed
  form `new_seed = 13*seed + 7`.
- Confirmed via the evidence index that every one of the 23 recorded path
  classes calls at least `1B3032`+`1B5256`+`1B6794` (no fixture exercises
  the `D7 >= 0xC8` skip-first-spawn arm as its primary recorded path).
- Did not attempt a boundary planner or `game.*` semantics; no
  `factcheck check` was run against this entry (nothing to check yet).
