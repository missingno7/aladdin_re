## Code

`NEW_GODS_SUBSYSTEM`: a resumable coroutine that stores its own
continuation address back into a live record (`move.l #<addr>,(a3)+`) and
dispatches through it (`movea.l (a3)+,a0; jmp (a0)`), matching the
escalation condition verbatim -- "an interpreter, a dispatcher family or a
data structure that needs its own semantic module and naming before any
leaf can be planned."

## Observed

Both copies share one shape, a classic four-octant Bresenham line
walker, reached through **two different entry conventions**:

- **Resume** (`0093D2`, `010000`): `movea.l a3,a5; movea.l (a3)+,a0;
  move.w (a3)+,d4; move.w (a3)+,d6; move.w (a3)+,d0; movem.w (a3)+,
  d2-d3/d5/d7; movea.l a5,a3; jmp (a0)` -- reads an 18-byte record
  (continuation ptr, d4, d6, d0, then d2/d3/d5/d7 packed) and jumps
  straight into whichever of four internal loop bodies the *last* call
  re-armed.  `00FFF0` only ever uses this entry.
- **Cold start** (`0093E4`, `010002`): given fresh d0/d1 (target) and
  d2/d3 (origin, `0091BC` sets these to camera+offset before the call),
  computes `|dx|`, `|dy|`, the direction sign, and which of the four loop
  bodies applies (`cmp.w d2,d0` selects the quadrant pair; `cmp.w d3,d2`
  selects steep vs shallow within it), then falls into the same loop body
  the resume entry would jump to. `0091BC` uses this entry, once, after
  finding a free slot.

The four loop bodies within each copy (`009408`/`009436`/`00947A`/`0094A8`
for the `0093E4` copy; `010022`/`010052`/`010098`/`0100C8` for the `010000`
copy) are themselves bounded and self-contained -- no calls out, RAM
writes confined to the shared budget word `FFFFF1FE` and the caller's own
record -- but the two copies **use a different loop-exit mechanism**: the
`010000` copy's inner loop is a real `dbra d7,<body>` (checks the shared
budget *and* a per-call iteration count `d7`, so a fully "walked" line
stops re-arming productively), while the `0093E4` copy's inner loop is an
unconditional `bra.b <body>` with `d7` only decremented once, after the
loop, when the budget runs out (so the line never signals "complete" from
inside the coroutine -- termination is presumably the caller's problem,
e.g. `0091BC`'s own driver at `009210`-`0092A4`, which polls one pool slot
per frame, calls the resume entry, and on a tile-collision test after it
returns frees the slot and fires an effect through the already-recovered
`00932C`).  Confirming that reading needs tracing the driver and the tile
test, neither of which is on this session's list.

`0091BC` itself (`0091BC`-`0091F6`), disassembled and cross-checked
against real per-instruction traces on all 32 fixtures: scans a 20-entry,
22-byte-stride pool at `FFFFE19E` (`tst.l (a3); bmi.b` -- free slots hold
`-1`) for up to 20 entries; every one of the 32 witnessed calls finds a
free slot on the first or a later entry (the "pool full" decline arm is
real ROM code, `0091DE`, but unwitnessed).  On a hit it stores two
caller-supplied auxiliary words at record offsets `0x12`/`0x14` (untouched
by the coroutine body itself -- read by something later, not traced), then
calls the cold-start entry `0093E4` once and sets a global flag
(`FFFFF386`).  All 32 fixtures land on exactly one of four `0093E4`-return
addresses (`00942E`, `00945C`, `0094A0`, `0094CE` -- the four loop bodies'
own tails), confirming the quadrant split is real and witnessed in full.
Example: `0091BC-entry-p0.state`
(SHA-256 `154c52d91777ab874f19a08aba48546763446bc083ad20affb4e42b4ae6c737e`),
64 instructions, returns via `0094A0`; `0091BC-entry-p7.state`
(SHA-256 `2b1ede820ce448b9eb8201b32c8fe6ce88d3122bdc3564f0c7fc4fc71264b3b8`),
83 instructions, returns via `00942E`.

`00FFF0` itself is a two-instruction shim into the resume entry
(`movea.l a3,a5` is `0093D2`'s/`010000`'s own first instruction -- `00FFF0`
*is* `010000`, there is no separate shim).  All 170 witnessed occurrences
land on one of four continuation addresses already known from the record
(`010022`, `010052`, `010098`, `0100C8`), i.e. every witnessed object was
already mid-walk (the cold-start / very first call for a given record is
never observed from this entry on any of the eight recordings -- it must
happen through a different caller that was not on this session's list).
Example: `00FFF0-entry-p0.state`
(SHA-256 `bfe437772f7a8e66364daa87d43fc5ccb4e45fbd2a2ac849090023df430603e0`),
21 instructions, `010022`; `00FFF0-entry-p2.state`
(SHA-256 `2b850a049bf71d6399d2bf8b594dc76ffa9d224045a97ce42261c538e46db75b`),

## Why the current mechanism does not fit

Neither entry is a single bounded leaf on its own terms: each is a
dispatch, through a value stored in a live record, into one of several
internal bodies -- the exact shape the grinder-protocol's object-record
carve-out reserves for a genuine convention, not a plain caller-supplied
record read.  The two independent ROM copies compound this: a shared
semantic module would need to (a) model the loop body generically enough
to serve both `009408`-family and `010022`-family addresses without
hand-duplicating the arithmetic, (b) get the `dbra`-vs-`bra.b` termination
difference right (the `010000` copy signals line completion through `d7`
in a way `0093E4`'s copy does not), and (c) carry the register
upper-16-bit-preservation quirk through the cold-start entry correctly
(`0093E4`'s `move.w d0,d4` only overwrites d4's low word, so the record's
own `d4` field inherits the upper half of whatever `0091BC`'s caller left
in d4 before the call -- a live instance of this session's recurring
masking-bug class, not yet isolated from a real fixture).  Both `0091BC`
and `00FFF0` are provably *bounded* (every witnessed loop terminates
against the shared budget word, no unbounded iteration was observed), so
this is not a hard "cannot be modelled" wall -- it is comparable in scope
to the `pickup_check`/`grid_inverse_award` recoveries this session
completed (a multi-arm composition with real, iteration-count-dependent
cost formulas), and there was not enough session budget left to take it
through fact-verification, segment/history-verify and a mutant to the
usual standard after `010CD2` and before the trigger evaluator's firing
arm (this session's next item).

## Resolution (17 September 2026, partial)

no new convention was needed.  `00FFF0`'s resume was recovered as its own
leaf candidate `walker` (`game/walker.py`: `start`/`run`/`load`/`stores`,
two copies, the re-arm table -- see `ledger.md` 2026-09-16), a plain
