## Where

  `003284` tail (returns observed at `003324`, `0033A6`, and other slots;
  `docs/gods/blockers/2026-09-19-003186.md`'s own reconnaissance named this

## Code

`NEW_GODS_SUBSYSTEM`.  The bounds-check head (`003480`-`0034B0`: `tst.w
$ef3c` bypass, then an x-range and a y-range test against `$f18c`/`$f18e`,
the camera position) *is* exactly the small gate the reconnaissance named,
and both its short exits are real: `0034B6: clr.w -(a7); rtr` (pass/bypass)
and, reached only from deeper inside the body, `0034BE: move.w #$8,-(a7);
rtr` (fail) -- both `00B8C2`'s own convention.  But **every retained
fixture's own trace** (`factcheck facts --path` run on all 40 fixtures of
`f0ac19738f19`, and a sample of the other four recordings) shows the
function does NOT return at the bounds check: the in-range arm
(`0034B0 ble.b $34c4`, taken in 35 of 40 fixtures on this recording) falls
through into a second, much larger body reaching `0034B8`/`0034C2` only
after real additional work -- confirmed by tracing, not guessed from the
ROM:

1. `0034C4`-`0034EA`: reads `+4(a0)` (an object status), declines (`bge.w
   $3620`) to a THIRD body when `>= 0xC0`; otherwise indexes a RAM table
   at `FFFFF8C2` (6 bytes/entry, by the status) and dispatches on its own
   `+4` word: `>1` -> the fail exit directly; `==1` -> a further
   range/table dispatch at `00354C` over a 4-entry RAM table at
   `FFFFF22E`; anything else falls through to (2).
2. `0034F0`-`003548`: a sound-request write (`FFFFFDF6 <- 0x34`), then a
   ROM-constant scan (`0x14B42`, up to 192 bytes, counting zeros in the
   first `status+1` of them -- data-independent given the status, i.e. a
   pure function of one RAM value over a ROM table), doubled twice into an
   index into a 16-entry ROM function-pointer table at `0x5958` (a SECOND
   real indirect-`jsr` table, the same shape as `003186`'s own `0x370E`
   finding; one entry, `0x5984`, IS the already-recovered `0075D6` platform
   tail), `jsr (a0)`, then `bsr.w $2f2e` (see below) before rejoining the
   shared exit.
3. `003620`-`003648` (the `>= 0xC0` arm, real and witnessed -- 3 of 40
   fixtures on `f0ac19738f19`, exit `003BE0`): `jsr $12c80.l` directly (the
   SAME pickup-award entry `003186`'s own blocker already named
   unrecovered), confirmed by `factcheck facts`' own call trace: `003632 ->
   012C80`, which itself calls `012CCA -> 012CD6` twice before returning --
   real internal calls into ROM this project has not read yet, distinct
   even from the `012D30`/`012A3E`/... chain `003186`'s blocker listed
   (same neighbourhood, different entry addresses -- `012C80`'s own
   internals are wider than one straight-line chain).  Then `bsr.w $2f2e`
   and rejoin.
4. `002F2E` (`bsr`'d from both (2) and (3)): a real, SELF-CONTAINED 10-slot
   queue append at `FFFFF09E` (10 bytes/entry, free slot marked by a
   negative first word) -- bounded, RAM-only, plain `rts`, no unrecovered
   callee.  This one piece IS a clean leaf on its own (the `pool shape`
   the Decision's own text names for `FFF262`), but it sits inside, not
   ahead of, this blocker's own body.  Its own DRAIN half (`0x2F68`,
   pulling the queue's own head and calling `0x011468`) is not reached
   from `003480` at all -- a separate, still-unrecovered caller.
5. `00354C`'s own "no F22E match" arm (`003590`-`0035B2`+): a second sound
   request cluster, a `+2(a1)`/`$f296` accumulation, then `bsr.w $364c` --
   a real, self-contained number-to-digits routine (seven `divs.w #$a`
   steps, each feeding one of three digit-encoder callees, `0x36C6`/
   `0x36CA`/`0x36CE`/`0x36D2`) whose own further destination (a text/score
   display?) was not traced to its end this session.

## Why the current mechanism does not fit

The reconnaissance in `docs/gods/blockers/2026-09-19-003186.md` (ROM read
only, no trace) undersold this region: it is not "a screen-visibility gate
returning through `rtr`" so much as a compound per-object post-processing
dispatcher that happens to open with one.  It shares a real unrecovered
callee (`jsr $12c80`) with the pickup-award integration the Decision's own
order placed LATER (bite 5, "`012C80` and its chain"), a second real
indirect-`jsr` function-pointer table (`0x5958`, alongside `003186`'s own
`0x370E`), and at least one more self-contained mechanism (a
number-to-digits routine, `0x364C`) whose own destination is unread.
Census bounded (no overflow) is necessary but not sufficient for a small
leaf: the 4-522 instruction spread and the five distinct real
sub-mechanisms above are `NEW_GODS_SUBSYSTEM` scale on the same standard
`003186`'s own escalation used, not a family over one witnessed selector.
