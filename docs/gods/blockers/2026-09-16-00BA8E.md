## Observed

`00BA8E`'s body (`00BA8E`-`00BBCA`, disassembled fresh this session):

1. `00BA8E`: `bsr.w $bcce` (the already-recovered `zone_check`), then a
   screen-distance accumulator over two axes (`FFF382`/`FFF384`, wrapping
   at `0xD0`/`0x150`) with several early-outs (`bmi.w`/`beq.w $bbc6`) once
   the wrapped total reaches zero or goes negative -- all RAM-only.
2. `00BACE`-`00BADC`: a sound-cue request (`FFFDF4`, values `0x3C`/`0x4F`)
   gated by `FFF396`, RAM-only.
3. `00BB36`-`00BB4E`: an optional append into an array at `FFF1E8` (a
   caller-supplied cursor, counted at `FFF1E2`), RAM-only.
4. `00BB4E`-`00BBCA`: a bounded neighbourhood scan -- a computed jump
   (`00BB84`-`00BB92`, `jmp (a1)`) into an unrolled loop testing 1-10
   bytes per row of a grid table (`00BB56` onward, the same
   asr/andi/adda arithmetic `0063FA`/`00FDB8`/`010CBC` share), for up to
   `D7+1` rows.  If every tested byte is zero, the scan falls through to
   `00BBC2`/`00BBC6`/`00BBCA` (restore, restore, rts) -- a clean, bounded,
   RAM-only exit, witnessed on 25 of the 32 real path classes (all showing
   `calls: ['00BCCE']` only, e.g. fixture `00BA8E-entry-p0.state`,
   SHA-256 `b55c19985f592c4d7bf6971202f901ad502a69de1d47e734d628ca46159cc8df`,
   `instructions: 116`, `last_pc: 00BBCA`).
5. If any tested byte is non-zero, `00BBCC` calls `jsr $13264.l`
   unconditionally (7 of 32 classes, e.g. fixture
   `00BA8E-entry-p17.state`, SHA-256
   `5cb08f4441431aac82f61c1517ea7c8e02056a10187bedc4566d015704a1b34b`,
   `instructions: 210`, ending `calls: ['00BCCE', '013264', '014A3C',
   '014A3C', '00932C']`).

`013264` itself (disassembled fresh): reads a byte from a caller-supplied
record, ranges it into one of three tracked-id tables (`FFEF8C`/`FFF01E`/
`FFF0B0` -- the same triple `conditions.py`'s kinds 3/4 already read), then
**loads a function pointer from a ROM table at `12D04` indexed by the
ranged value and jumps through it** (`movea.l (a1,d4.w),a1` after building
the table address) -- a genuine per-type dispatch into handlers this game
has no convention for yet, not a bounded leaf.

`010CD2` (disassembled fresh): calls `00BA8E` once (`010CE2`), unconditionally
usable; a second block reached from elsewhere in the same neighbourhood
(`010CF8`-`010D7A`) calls the **unrecovered** `0091BC` on one path
(`010D32`, gated by `FFF25A`/`FFF25C` reload timers) and, on the other two,
`01158C`/`0115D4` (the same shape `game/timers.py`'s own
`'trigger-reject'`/`'trigger-spawn'` sub-arms already reproduce at their own
addresses, but never as a direct call here); just past that, `010D7C`
(`cmpi.w #$3d,d2; beq...`) branches on a literal state value into more code
not traced this session -- a per-state dispatch, confirming the 15 Sep
note's own reading.

## Why the current mechanism does not fit

`013264`'s jump through `12D04` and `010CD2`'s branch at `010D7C` are both
dispatches through a type/state value into handlers this game has not
recovered and has no object-record convention for (the rule the
grinder-protocol's "caller-supplied record" clause explicitly carves out:
*"What genuinely needs the object-record convention is a dispatch through
a type byte into handlers that are not recovered... that is a composition
question, not a leaf's"*).  `010CD2`'s other path calls `0091BC`, itself
unrecovered.  Recovering `00BA8E`'s own "no neighbour found" arm alone is
in-rule (RAM-only, bounded, no unrecovered call) but was not carried
through this session: it needs the full screen-distance-accumulator
formula (two wrapping axes, several early exits) derived and verified
across the 25 witnessed "clean" fixtures plus the sound-cue and array-
append side effects, comparable in scope to the three regions this
session did complete, and there was not enough of the session budget left
to do it to the same standard (fact-verified, not hand-counted) after
`00364C`, `00462C` and `00F828`/`00F86A`.

## Resolution (supervisor, 16 September, later the same day)

The table at `012D04` holds eleven *record addresses* (work RAM `FFF552`
onward, 0x50 bytes apart), not handlers: `movea.l (a1,d4.w),a1` loads the
item record of the group's active id and `move.w $8(a1),$f35a.w` reads its
value; there is no jump.  `013264` is a RAM-only leaf and is recovered as
`pickups` (`game/pickups.py`, `pickup_award_plan`); its code −4 arm, which
continues into `013316`, is declined.  `010CD2`'s `cmpi.w #$3d,d2; beq` is
a single literal test, not a dispatch.  The remaining open items of this
package are `0091BC`, `013316`, `014A3C` and `00932C` as callees, and
`00BA8E`'s own clean arm — leaves for the grinder under the
caller-supplied-record rule, not a new subsystem.
