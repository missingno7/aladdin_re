# Blocker: `005700`'s own shared tail -- every state handler needs it, and it is its own subsystem

## Where

`005700`, the player state machine (29 states over `FFF192`, table
`005618`).  Not one state's own handler body: the shared tail every
witnessed activation falls into, `0075D6`-`0013CE` (the dispatcher's own
"inactive" arm and every one of the 29 table handlers but state 7's bare
`rts` all end in `bra.w $75d6`).  Census: a full-history tally of
`FFF192` at every `005700` gate hit (not the shared census tool -- see
"What was tried"), all eight recordings; `artifacts/gods/evidence/
census-005700-plain` (three raw entry snapshots) and `artifacts/gods/
evidence/census-00773A-fb408bc75597` (406 fixtures, 399 real path
classes, the tail's own first call censused on its own).

## Code

`NEW_GODS_SUBSYSTEM`.  The tail is not a small helper call; it is at
least three further mechanisms behind one shared entry point, none of
them recovered:

1. **The tile trigger scan** (`00773A`/`0077A8`): a bounded, RAM-only
   leaf when it finds nothing (43% of 13,519 occurrences on
   `fb408bc75597…`) -- characterised as *semantics only* this session
   (`game/player.py: tile_trigger_scan`, verified against every retained
   fixture, `tests/games/gods/test_player.py`) but not registered as its own
   candidate: a leaf with no durable effect at all (every register it
   touches is dead by the tail's own next two instructions, and it
   writes no RAM) has no mutant the game can see, so it waits to be
   composed into a parent whose own effects are real.  When it finds a
   tile over the threshold it declines, cascading through the event
   table at `004494` into further unrecovered code (creature/solid spawn
   logic through `00FB2C`, itself reaching the walker's own cold start
   `010002` -- real, deep, unrelated machinery, not modelled here).
2. **A camera-relative window clamp** (`0075E2`-`00766F`ish): `FFFFF3EE`/
   `FFFFF3F0`, a tracked pair distinct from the real camera
   (`camera.py`'s `CAMERA_X`/`CAMERA_Y`), stepped toward
   `POSITION_X`/`POSITION_Y` by 4 within bands (0x50/0xD0 in x; a
   `FFFFEF4E`-gated comparison in y) -- RAM-only as far as traced, not
   disassembled past its own branches into (3).
3. **A second, distinct inline sprite/tile upload** (`001312`-`0013CE`):
   reached by an unconditional tail `jmp` from `0076AA`, re-indexing
   `STATE_TABLE` at `STATE_INDEX + STATE_COUNTER` first (`007670`-`007696`,
   its own small table lookup, not `005700`'s own dispatch).  Its own
   `movem` frame, its own camera-subtracted descriptor lookup through the
   SAME ROM table `066794` `game/sprites.py` already names, and a
   register-counted `move.l (a0)+,(a6)` loop (traced once: 192
   longwords, 768 bytes) into the VDP data port -- `0018C8`'s own seam
   shape (recipe 6b), but a different ROM routine with its own
   descriptor convention, comparable in size to what `00126A`
   (`particle-emit`) took.  Its own `rts` pops the ORIGINAL caller's
   return address directly (a platform tail, `0048B4`'s own shape), so
   there is no further code of `005700`'s own to plan after it -- but
   getting there needs (2) modelled first, and its own descriptor/table
   logic needs the same discovery (2) and (3) still lack.

Any ONE of the 29 states' own composition needs the WHOLE of this tail
(or an early decline out of it) modelled first, because every witnessed
handler flows into `0075D6` unconditionally.

## Why the current mechanism does not fit

Recipe 6a (one gate, the states as arms) needs every arm to be a small
leaf or a call into already-recovered code once dispatched.  Here the
COMMON TAIL every arm shares is neither: it is itself a composite of a
leaf-when-clean scan that cascades into deep unrecovered code when it is
not, an unmodelled camera-window clamp, and a second sprite-upload seam
with its own descriptor table -- three separate pieces of real size, none
of them a state handler's own concern.  No state's own composition can
be admitted end to end without them, and there is no OTHER witnessed exit
from `005700` to fall back on (state 7, the only handler that skips the
tail, is real ROM code no recording ever enters).  This is squarely
`NEW_GODS_SUBSYSTEM`: a structure needing its own naming (what
`FFFFF3EE`/`FFFFF3F0` and the `007670` table actually represent) before
any leaf here -- state or tail -- can be planned as a whole.

## Decision (supervisor, 17 September)

The tail is one region of a known shape, not a new subsystem: a
**platform-tail seam** (recipe 6b, `0018C8`'s and `0047DA`'s shape) whose
prefix is RAM-only semantics and whose ceded operation is the player's
sprite upload.  Gate `0075D6` (a `bra.w` target; gate-able, checked).  The
prefix, in order: the tile trigger scan `00773A` (its clean arm is
already semantics, `game/player.py: tile_trigger_scan`; the found arm —
an event raised through `007850` — is **declined** for now, named); the
**follow point** step (`FFF3EE`/`FFF3F0` are `camera.py`'s `FOLLOW_X`/
`FOLLOW_Y`, the target the recovered camera follow `002806` already
consumes: the tail moves the follow point toward the player's position
by 4 per tick within the bands at `007606`–`00766C`, clamped to `0xEC0`
and `0x340` — that is the camera subsystem's other half and belongs in
`game/camera.py`); the `00755A` arm at `0075F8` (census it: recover if
bounded, decline named otherwise); the state-table re-index at
`007670`–`007696`.  The ceded operation: from `0076AA`'s `jmp 001312` to
the upload's own `rts` (the caller's return is popped there, so there is
no suffix — `0048B4`'s shape).  Cost and residue from the tracer on the
retained `census-00773A` fixtures re-parked at `0075D6`.

Once `0075D6` is a candidate, every state handler composes as a leaf
owning its own body and the jump into the recovered tail — `004790`'s
shape over `0047DA` — and `005700` is the family over `FFF192`.  The tail
is the first bite; the states follow in frequency order (1, 0, 5, 14).
